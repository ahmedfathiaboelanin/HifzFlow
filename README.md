# HifzFlow — React + TypeScript + Vite

تطبيق محلي أولاً (local-first) لحفظ القرآن ومراجعته بالتثبيت والتكرار المتباعد.
لا خادم، لا حساب، لا مزامنة سحابية في هذه النسخة — كل بياناتك في IndexedDB على جهازك.

## التشغيل

المتطلبات: **Node.js 20+** و npm.

```bash
npm install
npm run dev      # تشغيل للتطوير على http://localhost:5173
npm run build    # بناء نسخة الإنتاج إلى dist/
npm run preview  # معاينة نسخة الإنتاج محلياً
```

أوامر إضافية:

```bash
npm run fetch-quran   # إعادة جلب النص العثماني من AlQuran Cloud وإعادة توليد البيانات
npm run simulate      # محاكاة والتحقق من قواعد التثبيت والتكرار المتباعد
```

## التقنية (حسب المواصفات المطلوبة)

- **React 19 + TypeScript + Vite**
- **Tailwind CSS** (مع نظام ثيمات بـ ٥ لوحات × فاتح/داكن/تلقائي عبر CSS variables)
- **Redux Toolkit** (حالة التطبيق) + **Dexie.js + IndexedDB** (التخزين الدائم)
- **React Hook Form + Zod** (النماذج والتحقق)
- **Recharts** (الإحصائيات) + **Framer Motion** (حركات خفيفة)
- **vite-plugin-pwa** (قابل للتثبيت على Windows و Android، يعمل دون اتصال بعد أول تحميل)

### ملاحظة صريحة عن shadcn/ui

المواصفات طلبت shadcn/ui. بدلاً من تثبيت shadcn CLI كاملاً (الذي يسحب مكونات Radix كثيرة ويحتاج إعداداً إضافياً)، بُنيت مكونات واجهة محلية في `src/components/ui.tsx` **بنفس نمط shadcn وواجهته** (Button / Card / Input / Select / Tabs / Dialog / Badge) — نفس الشكل والسلوك، دون اعتماديات Radix. إن أردت مكونات Radix الأصلية لاحقاً يمكن إضافتها فوق نفس الواجهة.

## البيانات

- النص العثماني الكامل مضمّن محلياً في `src/data/quran.json` — **١١٤ سورة / ٦٬٢٣٦ آية** (مصدره AlQuran Cloud `quran-uthmani`، نص تنزيل)، وملف `src/data/mushaf.ts` فيه خريطة المصحف المدني (٦٠٤ صفحات + الأجزاء).
- جُلبت البيانات بواسطة `scripts/fetch-quran.mjs` والتحقق منها آلياً: ١١٤ / ٦٬٢٣٦، الصفحات ١–٦٠٤، وفحوصات موضعية (ص١ الفاتحة، ص٢ البقرة ١–٥، ص٥٨٢ بداية الجزء ٣٠).
- البحث العربي يتجاهل التشكيل.
- النص مرجع للمراجعة — التطبيق يعرض تذكيراً بالتحقق من المصحف.

## التخزين

قاعدة Dexie باسم **`HifzFlowDB`**، الجداول: `memorizationProgress`, `revisionPlans`, `revisionTasks`, `revisionSessions`, `revisionHistory`, `mistakes`, `bookmarks`, `focusSessions`, `distractions`, `dailyTasks`, `recurringTasks`, `userPreferences`, `wirdCompletions`.
تُحمَّل الحالة من IndexedDB قبل أول عرض، وتظهر حالة التخزين في الشريط الجانبي؛ وإن كان IndexedDB محظوراً يعمل التطبيق في الذاكرة مع تحذير صريح.

### طبقة المستودعات والمزامنة

`src/lib/db.ts` فيه مستودع (repository) لكل جدول (CRUD فقط)، وواجهة `SyncProvider` فارغة في هذه النسخة (`NoopSyncProvider`) — محول Supabase مستقبلي يطبّق نفس الواجهة دون تغيير المزايا.

## القواعد المثبتة في هذا الإصدار

- **الختمة كل ١٥ يوم:** كل يوم ٥ صفحات ضعيف + ١٥ متوسط + جزء قوي (٢٠ صفحة) = جزآن. البانر يحسب هدف الختمة (٣٠ جزءاً / ٦٠٤ صفحات) ويتحدث عند تغيير الحصص (ضعيف ٥/٦/٧، متوسط ١٠/١٢/١٥، قوي ٢٠/٢٢/٢٥).
- **الختمة (khatma):** كل ختمة تغطي كل المحفوظ مرة واحدة، وأيامها تخلط المستويات الثلاثة بالتوازي. السور تُقسَّم إلى مقاطع متوازنة حسب حصتها اليومية (يونس الضعيفة، ١٤ صفحة = ٣ مقاطع ٥+٥+٤).
- **لا ترقية تلقائية بعد الختمة إطلاقاً.** الضعيف يصبح متوسطاً فقط بعد إكمال دورة التكرار المتباعد كاملة: ٦ مراحل (١، ٢، ٣، ٥، ٧، ١٠ أيام) بتقييم جيد/سهل في المرحلة الأخيرة. «سهل» مرتين متتاليتين لا يكفي للضعيف، و«أعد» يعيد الدورة من الأول. والمتوسط يُغطى كل يوم بالتوازي فلا يُنسى.
- **بعد التثبيت:** تُراجع السورة مع المتوسط كل ١٥ يوم (افتراضي)، مع خيار دورة ١٠ أيام من بطاقة التثبيت.
- **فواصل التكرار المتباعد:** ضعيف ١،٢،٣،٥،٧،١٠ • متوسط ١،٣،٧،١٠،٢٠،٣٥ • قوي ١،٣،٧،١٤،٣٠،٦٠ • متقن جداً ٢،٧،١٤،٣٠،٦٠،٩٠.
- **جدول الورد الدوري:** من المحفوظ الفعلي بترتيب المصحف، دورة قابلة للاختيار (٧/١٠/١٥/٣٠ يوماً)، «تم» لكل يوم تُحفظ في IndexedDB، والدورة التالية تبدأ تلقائياً.
- **تقسيم الورد بالدقائق:** ٥٠٪ مراجعة دورية / ٣٠٪ مراجعة حديثة / ٢٠٪ حفظ جديد وربط، مع تحذير إن تجاوز ورد اليوم حصته.

## نقل بياناتك من النسخة المستضافة

النسخة المستضافة من HifzFlow تصدّر نسخة JSON من صفحة «النسخ الاحتياطي».

1. في النسخة المستضافة: النسخ الاحتياطي ← «تصدير نسخة احتياطية» (ملف `.json`).
2. هنا: النسخ الاحتياطي ← «استيراد نسخة احتياطية» واختر الملف.
3. يُتحقق من بنية الملف (Zod) ويُطلب تأكيدك قبل الاستبدال — نفس الجداول ونفس الصيغة، فتنتقل بياناتك كما هي.

ملاحظة: IndexedDB مرتبط بنطاق (origin) كل نسخة، لذلك لا تنتقل البيانات تلقائياً — النقل يكون عبر ملف النسخة الاحتياطية كما هو موضح أعلاه.

## أول تشغيل

يأتي التطبيق مع **بيانات تجريبية موسومة بوضوح** (سور وأخطاء ومهام وهمية) لترى شكله. امسحها بضغطة واحدة من لوحة التحكم أو من «النسخ الاحتياطي» ← «مسح البيانات التجريبية والبدء فارغاً».


## ضبط المتشابهات

طُبِّق تطبيق «ضبط المتشابهات — الماهر بالقرآن» داخل HifzFlow كصفحة أصلية (وليس iframe):

- **البيانات:** `src/data/mutashabihat.json` — ٥٩٦ مدخلًا و١١٧٢ آية موثّقة، مستخرجة من النسخة المستقلة.
- **المنطق والأنواع:** `src/lib/mutashabihat.ts` — التطبيع العربي للبحث، فهارس السور والأجزاء والأنبياء، وإحصاءات التحقق.
- **الواجهة:** `src/pages/Mutashabihat.tsx` ومكوّناتها في `src/components/mutashabihat/` — تصفح وتصفية وترقيم، وبطاقات تفاصيل، ووضع اختبار من ١٠ أسئلة.
- **الدمج:** الصفحة مسجلة في شريط التنقل تحت «الدراسة»، ومسارها `#mutashabihat`، ومضافة كاختصار في PWA.
- **الثقة:** المدخلات غير الموثوقة معلّمة بوضوح، والآيات الموثّقة تُعرض بنص المصحف. تبقى المراجعة من المصحف مطلوبة.
